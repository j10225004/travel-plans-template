# 第8週: 外部のデータを使う と 前半のまとめ

## 今週のゴール

- プランの詳細ページに、行き先のこれから3日間の天気を表示する
- 前半8週でできるようになったことを振り返り、後半の「自分のアプリ」につなげる

## 1. 外部のサービスを使う

天気のように自分で用意できないデータは、それを提供しているサービスから受け取ります。サービスにデータを問い合わせる窓口を **API** といいます。
今回は **Open-Meteo**（https://open-meteo.com）という、登録や API キーなしで使える無料の天気サービスを使います。

プランの表には、行き先の緯度・経度（`latitude`・`longitude`）が入っています。これを API に渡すと、その場所の天気予報が返ってきます。

## 2. Claude に天気を表示してもらう（40分）

自分の言葉で頼んでください。決めておくとよいこと:

- どこに表示するか（例: 詳細ページの見どころの下）
- 何日分、何を表示するか（例: 3日分の天気と最高・最低気温）
- 天気を「晴れ」「雨」などの日本語で表示したい
- **天気サービスが止まっているときにどうするか**（例: 天気の欄だけ出さず、ページは普通に表示する）

最後の点は大切です。外部のサービスはいつも動いているとは限りません。止まったときに自分のサイトまで表示されなくなるのは避けたいところです。

## 3. 確かめる

- いくつかのプランで、行き先ごとに違う天気が表示されるか
- 天気の日本語が自然か
- スマホの幅で崩れないか
- Claude に「天気サービスにつながらないとき、ページがどう表示されるか確かめる方法を教えて」と聞いて、試してみる

## 4. 発展（任意）: AI でおすすめ文を作る

講師のデモで、Claude API を使って「この季節に行くならここがおすすめ」という文を自動で作る例を見せます。
自分でも試したい人は講師に相談してください（API キーを個別にお渡しします）。

試すときの約束:

- API キーは Vercel の環境変数に置き、名前に `NEXT_PUBLIC_` を**付けない**（付けると、サイトを見た人の画面に鍵が送られてしまいます）
- API キーを Claude への指示文や PR に貼らない
- 使いすぎると費用がかかるので、何度も自動で呼ばれる作りにしない

## 5. 前半のまとめ（30分）

8週間で頼んできた指示文を、提出した PR から振り返ります。Claude にも手伝ってもらえます。

```
これまでの自分の PR の本文を読んで、
自分の指示の出し方が最初と比べてどう変わったか、3つにまとめて。
```

振り返りの観点:

| 観点 | 振り返る問い |
| --- | --- |
| 具体性 | 「どこを・どうしたいか」を最初から言えるようになったか |
| 分割 | 大きな機能を手順に分けて頼めたか |
| 検証 | 何を確かめれば完成と言えるかを、先に決められたか |
| 安全 | 鍵や個人情報の扱いで迷ったところはどこか |

## 6. 提出

PR を作り、本番にマージしてから提出します。

- 「結果」欄: 本番 URL と、天気が表示されているプランの例
- 「来週やること」欄: 後半で作りたい「自分のアプリ」の案を1〜3個（業務の困りごとから考える。会社の情報は使わず、ダミーデータで作れるもの）
