# 演習の進め方

## この演習で身につけること

**作りたいものを言葉にして AI に伝え、できあがりを確かめて、直してもらう力**です。
コードを書けるようになることは目標にしません。コミットや PR といった操作も Claude にやってもらいます。あなたは「何をしてほしいか」と「できたものが合っているか」に集中します。

## しくみの図解

Codespaces・GitHub・Vercel の関係と、3種類の URL の違いは [how-it-works.md](how-it-works.md) にまとめています。迷ったら見返してください。

## 1週間の流れ（目安: 週2時間）

1. その週の教材（`docs/weekNN.md`）を読む（10分）
2. Claude に指示して作る・直す（80分）
3. プレビュー URL で確かめて、PR で提出する（30分）

## 毎週の提出

毎週、PR（変更の確認依頼）を作って提出します。PR の本文には次の4つを書きます。PR を作ると、この形の欄が最初から入っています。

1. **今週頼んだこと**: Claude に送った指示文をそのまま貼る
2. **結果**: プレビュー URL と、画面で確かめたこと
3. **うまくいかなかったこと と 言い直した指示**
4. **来週やること**

評価で一番見るのは 3 です。一度で思い通りにならなくて大丈夫です。どう言い直したかが学びになります。

## よい指示の4つのポイント

| ポイント | よくない例 | よい例 |
| --- | --- | --- |
| どこを | 「色を変えて」 | 「トップページの『プランを見る』ボタンの色を」 |
| どうしたいか | 「いい感じに」 | 「緑色に。文字は白のまま」 |
| 小さく分ける | 「サイトを全部作り直して」 | 「まずヘッダーだけ変えて。確認したら次を頼みます」 |
| 確かめ方 | （なし） | 「変えたら、どこを見れば確認できるか教えて」 |

## 守ること

- 会社の情報・顧客情報・個人情報は入れない
- パスワードや API キーを Claude への指示文に貼らない
- 作業の終わりには「push して」と頼む（Codespaces は長く使わないと消えることがあります）
- 困ったら [troubleshooting.md](troubleshooting.md) を見る。それでもだめなら質問チャンネルへ
