# 第6週: 問い合わせフォームを保存する

## 今週のゴール

プランの詳細ページに問い合わせフォームを付け、送られた内容をデータベースに保存する。
「誰が・何をしてよいか」を決める RLS（行ごとのアクセス制限）の考え方を知る。

## 1. 問い合わせの表を作る（5分）

第5週と同じ手順で、`supabase/02_inquiries.sql` を Supabase の SQL Editor に貼り付けて Run します。
Table Editor に「inquiries」という空の表ができれば成功です。

## 2. RLS を知る

フォームはサイトを見に来た誰でも使えます。もし「誰でも何でもできる」状態だと、他の人の問い合わせ（名前やメールアドレス）を誰でも読めてしまいます。
そこで、表ごとに「誰が・何をしてよいか」を決めておきます。これが RLS です。

| 表 | 見に来た人ができること | できないこと |
| --- | --- | --- |
| plans（プラン） | 見る | 追加・変更・削除 |
| inquiries（問い合わせ） | 書き込む | **見る**・変更・削除 |

問い合わせは「書き込めるけれど、見られない」ポストのような作りです。中身は、あなたが Supabase の管理画面から見ます（第7週ではサイトの管理画面からも見られるようにします）。

## 3. Claude にフォームを作ってもらう（40分）

自分の言葉で頼んでください。決めておくとよいこと:

- フォームをどこに置くか（例: プランの詳細ページの下）
- 入力してもらう項目（`02_inquiries.sql` の表には「名前・メールアドレス・問い合わせ内容・どのプランか」の欄があります）
- 送信した後に何と表示するか
- 送信できなかったときに何と表示するか

> 項目を増やしたいときは、表にも欄を足す必要があります。Claude に「表に欄を足す SQL も作って」と頼み、SQL Editor で実行してください。

## 4. 確かめる

1. プレビューで詳細ページを開き、**ダミーの名前とメールアドレス**で送信してみる（本物の個人情報は使わない）
2. Supabase の Table Editor →「inquiries」に、送った内容が入っていることを確かめる
3. 空のまま送信しようとしたらどうなるか、とても長い文を入れたらどうなるかも試す

うまくいかないときは、そのまま Claude に伝えましょう。エラーは、プレビューの画面で F12 キーを押し、「Console（コンソール）」タブに赤い字で出ています。

```
フォームを送信すると「送信できませんでした」と出る。
原因を調べて。エラーの表示はこれ:（貼る）
```

## 5. 提出

PR を作って提出します。「結果」欄には、送信できたことと、Table Editor で確認できたことを書いてください。
「うまくいかなかったこと」欄には、**送信後や失敗時の表示をどう決めたか**も書いてください。

## つまずいたら

| 症状 | 対処 |
| --- | --- |
| 「new row violates row-level security policy」と出る | Claude に「問い合わせは書き込みだけ許可している。保存した後に読み返さないようにして」と伝えます |
| 「relation "inquiries" does not exist」と出る | `02_inquiries.sql` を実行したか確認します |
| Table Editor に入っていない | 表示を再読み込みします。それでもなければ、送信時のエラーを Claude に伝えます |
